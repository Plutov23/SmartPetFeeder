# 第 2 章：STM32 工程与首次运行

## 本章目标

完成本章后，你应该能够：

- 打开并编译现有 Keil 工程
- 解释 STM32F103 的系统时钟来源
- 说清三个串口各自连接的模块
- 通过 USART1 查看带时间戳的运行日志
- 将固件烧录到开发板并判断程序运行到哪个阶段
- 理解主循环中 1 秒任务和 5 秒任务的调度方式

本章只验证 STM32 主控和调试链路，不要求云平台、视觉识别和小程序全部在线。

## 1. 准备开发环境

### 软件

- Keil MDK-ARM 5
- STM32F1 Device Family Pack
- ST-Link 驱动
- 串口终端，例如 MobaXterm、PuTTY 或其他串口助手
- 可选：STM32CubeMX，用于查看 <code>F103_Feeder.ioc</code>

当前工程验证环境：

| 项目 | 版本或配置 |
| --- | --- |
| MCU | STM32F103C8Tx |
| 编译器 | ARM Compiler 5.06 |
| CMSIS | 5.0.1 |
| STM32F1xx DFP | 2.2.0 |
| 调试器 | ST-Link |

使用其他版本通常也能编译。如果 Keil 提示编译器不存在，应先在 Target Options 中选择本机已经安装的兼容编译器，不要直接修改业务代码。

### 硬件

- STM32F103C8T6 最小系统板
- ST-Link
- USB 转 TTL 串口模块
- 稳定的 3.3 V 或 5 V 电源，具体取决于开发板供电接口
- 已接好的 HX711 模块

当前 HX711 驱动会等待 DOUT 变为低电平。如果完全没有连接 HX711，程序会停在称重初始化阶段。首次验证时至少应正确连接 HX711，或使用调试器观察程序停留位置。

## 2. 认识固件目录

STM32 固件位于：

~~~text
firmware/stm32f103/
├── Core/
│   ├── Inc/                  头文件
│   └── Src/                  应用和驱动源码
├── Drivers/                  STM32 HAL 与 CMSIS
├── MDK-ARM/
│   └── F103_Feeder.uvprojx   Keil 工程
└── F103_Feeder.ioc           CubeMX 配置
~~~

本章重点关注：

| 文件 | 作用 |
| --- | --- |
| <code>Core/Src/main.c</code> | 初始化顺序、主循环和串口中断 |
| <code>Core/Src/usart.c</code> | 三个串口的参数和引脚 |
| <code>Core/Src/gpio.c</code> | 普通 GPIO 初始化 |
| <code>Core/Inc/SystemLog.h</code> | 统一日志格式 |
| <code>Core/Src/SystemLog.c</code> | 将 printf 重定向到 USART1 |
| <code>Core/Inc/app_config.example.h</code> | 本地私密配置模板 |

## 3. 创建本地配置

固件编译时需要 <code>app_config.h</code>，但真实 Wi-Fi 和 OneNET 凭据不应提交到 Git。

在 <code>firmware/stm32f103/Core/Inc</code> 中复制模板：

~~~bash
cp app_config.example.h app_config.h
~~~

首次编译可以保留占位值。进入网络章节后，再填写：

- <code>WIFI_SSID</code>
- <code>WIFI_PASSWORD</code>
- <code>ONENET_PRODUCT_ID</code>
- <code>ONENET_DEVICE_NAME</code>
- <code>ONENET_TOKEN</code>
- <code>FEEDER_STEPS_PER_GRAM</code>

<code>app_config.h</code> 已被 Git 忽略。提交代码前仍应执行一次敏感信息检查。

## 4. 打开并检查 Keil 工程

打开：

~~~text
firmware/stm32f103/MDK-ARM/F103_Feeder.uvprojx
~~~

依次检查：

1. Target Device 为 STM32F103C8Tx。
2. 编译器已安装且可选。
3. Include Paths 包含 Core、HAL 和 CMSIS 头文件目录。
4. Debug 页面选择 ST-Link Debugger。
5. Utilities 页面使用与调试器匹配的下载算法。
6. Flash Download 中启用 Reset and Run。

点击 Build。成功时应看到 0 Error。警告也应逐条确认，不要把大量警告当作正常现象。

## 5. 理解系统时钟

<code>SystemClock_Config()</code> 使用外部高速晶振 HSE，并通过 PLL 倍频：

~~~text
HSE 8 MHz × PLL 9 = SYSCLK 72 MHz
~~~

总线频率为：

| 时钟 | 配置 | 结果 |
| --- | --- | --- |
| SYSCLK | HSE × 9 | 72 MHz |
| HCLK/AHB | SYSCLK ÷ 1 | 72 MHz |
| PCLK1/APB1 | HCLK ÷ 2 | 36 MHz |
| PCLK2/APB2 | HCLK ÷ 1 | 72 MHz |

如果开发板没有可用的 8 MHz 外部晶振，程序可能进入 <code>Error_Handler()</code>。此时应先确认板卡硬件，再决定是否改用 HSI，不能只通过反复烧录解决。

## 6. 外设初始化顺序

主函数先初始化 HAL 和系统时钟，然后初始化底层外设：

~~~text
HAL_Init
└── SystemClock_Config
    ├── GPIO
    ├── USART1
    ├── USART2
    ├── TIM3
    ├── I2C1
    └── USART3
~~~

随后初始化应用模块：

1. OLED
2. AHT20
3. DS1302
4. 定时喂食计划
5. 蜂鸣器
6. 步进电机
7. HX711
8. ESP-01S
9. MaixCam

这个顺序对排错很重要。串口日志停在哪一行，通常就说明程序在下一模块附近出现了问题。

## 7. 三个串口的分工

三个串口均为 8 数据位、1 停止位、无校验、无硬件流控。

| 串口 | 引脚 | 波特率 | 用途 |
| --- | --- | ---: | --- |
| USART1 | PA9 TX、PA10 RX | 9600 | 电脑调试日志 |
| USART2 | PA2 TX、PA3 RX | 9600 | MaixCam 状态协议 |
| USART3 | PB10 TX、PB11 RX | 115200 | ESP-01S 与 OneNET |

USB 转 TTL 连接 USART1：

~~~text
STM32 PA9  TX  -> USB-TTL RX
STM32 PA10 RX  <- USB-TTL TX
STM32 GND      -- USB-TTL GND
~~~

只查看日志时，PA10 可以暂时不接；GND 必须连接。

串口终端设置：

~~~text
Baud rate: 9600
Data bits: 8
Stop bits: 1
Parity: None
Flow control: None
~~~

## 8. 日志格式

项目统一使用 <code>APP_LOG</code>：

~~~c
APP_LOG("SYS", "Board power on...");
~~~

输出格式：

~~~text
[运行毫秒数][模块名] 消息
~~~

例如：

~~~text
[00000000][SYS] Board power on...
[00000125][WEIGHT] HX711 peeling start...
~~~

时间戳来自 <code>HAL_GetTick()</code>，单位是毫秒。模块标签可以帮助快速过滤日志：

- <code>SYS</code>：系统状态
- <code>WEIGHT</code>：称重
- <code>WIFI</code>：网络
- <code>SCH</code>：喂食计划
- <code>WARN</code>：异常恢复

## 9. 烧录与首次启动

1. 断开电机负载，保留 STM32、ST-Link、调试串口和 HX711。
2. 检查 ST-Link 的 SWDIO、SWCLK、GND 和目标电压。
3. 在 Keil 中点击 Download。
4. 复位开发板。
5. 打开 USART1 串口终端。
6. 保存完整启动日志。

启动日志至少应经过：

~~~text
[SYS] Board power on...
[WEIGHT] HX711 peeling start...
[WEIGHT] Manual taring start...
[WEIGHT] Tare done! New Offset: ...
[WEIGHT] HX711 Hardware initialized.
[WIFI] Connecting to OneNET...
~~~

如果网络尚未配置，ESP-01S 初始化可能失败或等待较长时间。这不影响你确认主控、日志和 HX711 已经开始工作。

## 10. 主循环如何运行

主循环没有使用长时间的固定周期延时，而是比较 <code>HAL_GetTick()</code>：

| 周期 | 任务 |
| --- | --- |
| 持续执行 | MaixCam 数据状态机、网络命令处理 |
| 每 1 秒 | 读取时间、重量，检查喂食计划，刷新 OLED |
| 每 5 秒 | 读取温湿度，向 OneNET 上报数据 |
| 每轮约 10 ms | 主循环呼吸延时 |

这种写法允许多个模块共享主循环。如果在其中加入几秒钟的阻塞函数，摄像头数据、网络接收和界面刷新都会被拖慢。

## 11. 常见错误

### Keil 提示找不到 ARMCC

- 安装 ARM Compiler 5
- 或在 Target Options 中选择当前可用的兼容编译器
- 清理工程后重新编译

### No ST-Link detected

- 检查驱动
- 检查 SWDIO、SWCLK 和 GND
- 确认目标板已经供电
- 降低 SWD 时钟后重试

### 烧录成功但没有日志

- 确认监听的是 USART1，不是 USART2 或 USART3
- 确认 9600、8N1、无流控
- 检查 TX/RX 是否交叉
- 确认 USB-TTL 与 STM32 共地
- 复位后重新观察启动阶段

### 日志停在 HX711 peeling start

当前驱动会一直等待 HX711 DOUT 拉低：

- 检查 HX711 是否供电
- 检查 PA11 是否连接 DOUT
- 检查 PA12 是否连接 SCK
- 检查模块和 STM32 是否共地

### 程序进入 Error_Handler

- 检查外部晶振
- 检查时钟配置是否与板卡一致
- 使用调试器单步确认失败的是时钟还是外设初始化
