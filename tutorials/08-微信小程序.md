# 第 8 章：微信小程序、云端数据与视频流

## 本章目标

完成本章后，你应该能够：

- 导入并运行微信小程序工程
- 配置 OneNET HTTPS API 和 MaixCam WebSocket
- 查看温湿度、余粮和进食记录
- 下发手动出粮命令
- 新增、修改、启停和删除喂食计划
- 理解本地记录和前端凭据的安全限制

## 1. 小程序的职责

小程序提供四类功能：

| 功能 | 数据来源或去向 |
| --- | --- |
| 温湿度、重量 | 从 OneNET 每 5 秒查询 |
| 手动出粮与计划 | 通过 OneNET 下发 |
| 进食健康记录 | 从 OneNET 获取后保存到本机 |
| 实时画面与识别标签 | 直接连接 MaixCam WebSocket |

视频不经过 OneNET，手机必须能够访问 MaixCam 的局域网地址。

## 3. 导入微信开发者工具

1. 打开微信开发者工具。
2. 选择导入项目。
3. 项目目录选择 <code>miniapp/wechat</code>。
4. 首次学习可以使用项目中的测试配置。
5. 正式调试和发布时改用自己的 AppID。
6. 确认基础库和当前项目语法兼容。

仓库中的 <code>project.config.json</code> 使用 <code>touristappid</code>，它不代表可以直接发布。

## 4. 创建本地配置

复制：

~~~bash
cp config.example.js config.js
~~~

填写：

~~~javascript
module.exports = {
  maixcam: {
    websocketUrl: 'ws://192.168.1.100:8765'
  },
  onenet: {
    apiBaseUrl: 'https://iot-api.heclouds.com',
    authorization: 'YOUR_ONENET_AUTHORIZATION',
    deviceName: 'YOUR_DEVICE_NAME',
    productId: 'YOUR_PRODUCT_ID'
  }
}
~~~

将 WebSocket IP 替换为 MaixCam 控制台输出的当前地址。

<code>config.js</code> 已被 Git 忽略。不要修改并提交示例文件中的占位值为真实凭据。

## 5. 云端数据查询

页面加载时立即查询一次，之后每 5 秒查询：

~~~text
GET /thingmodel/query-device-property
~~~

查询参数包含：

- <code>product_id</code>
- <code>device_name</code>

请求头包含 API Authorization。返回属性映射为：

| OneNET 标识符 | 页面字段 |
| --- | --- |
| <code>tem</code> | temperature |
| <code>wet</code> | humidity |
| <code>wei</code> | foodLevel |
| <code>eat_cnt</code> | 进食事件序号 |
| <code>eat_time</code> | 进食时长 |
| <code>eat_weight</code> | 消耗重量 |

页面卸载时会清除轮询定时器，避免后台重复请求。

## 6. 进食健康记录

小程序用 <code>eat_cnt</code> 判断是否为新事件：

1. 读取本地 <code>last_eat_cnt</code>
2. 与云端事件序号比较
3. 新事件写入 <code>feed_logs</code>
4. 最多保留 50 条
5. 更新今日和累计统计

记录使用 <code>wx</code> 本地存储，不是云数据库。因此：

- 清理小程序数据后记录会丢失
- 换手机后不会自动同步
- 多个用户看到的本地历史可能不同
- 云端只保留当前属性值时，旧事件无法完整重建

## 7. 手动出粮

页面提供三个快捷选项：

| 选项 | 出粮量 |
| --- | ---: |
| 喂猫咪 | 20 g |
| 喂狗狗 | 50 g |
| 试出粮 | 5 g |

小程序调用：

~~~text
POST /thingmodel/set-device-property
~~~

负载：

~~~json
{
  "params": {
    "feed_amount": 20,
    "feed_cmd": 1
  }
}
~~~

平台返回成功只表示请求被接受，不等于实际已经出粮。演示和测试时还应观察 STM32 日志、电机动作和真实重量。

## 8. 喂食计划

每个计划包含：

- 编号 0 到 4
- 时间
- 出粮克数
- 是否启用

保存或切换计划时下发：

~~~json
{
  "sch_id": 0,
  "sch_h": 8,
  "sch_m": 30,
  "sch_w": 20,
  "sch_en": 1
}
~~~

小程序最多创建 5 个计划。删除计划时，会向设备下发同一编号并将 <code>sch_en</code> 设为 0。

当前计划列表没有持久化到云数据库，STM32 计划也只保存在 RAM。设备复位后，应重新切换或保存计划以同步硬件。

## 9. 连接 MaixCam 视频

页面通过：

~~~javascript
wx.connectSocket({
  url: config.maixcam.websocketUrl
})
~~~

收到 JSON 后：

1. 解析 <code>image</code>
2. 添加 <code>data:image/jpeg;base64,</code> 前缀
3. 更新画面
4. 显示 <code>pet</code> 标签

连接条件：

- MaixCam 已运行视觉程序
- 手机或开发者工具能访问 MaixCam IP
- 端口 8765 未被阻止
- 配置中的 IP 没有过期

局域网 DHCP 可能改变 IP。长期使用时可以配置地址保留或增加设备发现机制。

## 10. 推荐调试顺序

### 只验证页面

先确认页面能够编译、切换标签和打开弹窗。

### 验证 OneNET 查询

关闭视频也可以测试：

- 请求是否返回 200
- OneNET 业务码是否为 0
- 属性数组是否包含正确标识符
- 页面数字是否每 5 秒更新

### 验证命令下发

先使用 5 g 试出粮，并同时观察：

- 开发者工具 Network
- OneNET 控制台
- STM32 USART1
- 电机动作

### 最后验证视频

确认 MaixCam 和电脑在同一局域网，再连接 WebSocket。不要把云端问题与局域网视频问题混在一起排查。

## 11. 开发与发布差异

开发者工具中可用于局域网调试的配置，不一定满足正式发布要求。正式版本应按照微信平台当前要求处理：

- request 合法域名
- WebSocket 合法域名
- HTTPS 与 WSS
- 域名备案和证书
- 用户隐私说明
- 网络和设备权限

不要为了让开发环境临时通过而忽略正式环境的安全要求。

## 12. 前端凭据风险

当前小程序直接保存 OneNET API Authorization。任何能获取小程序包或调试流量的人，都可能看到该凭据。

更安全的架构：

~~~text
微信小程序
  ↓ 用户身份 + 受限请求
自己的后端
  ↓ 保存并使用平台凭据
OneNET
~~~

后端应：

- 验证用户身份
- 限制可访问的设备
- 限制出粮量和频率
- 记录操作日志
- 隐藏 OneNET 高权限凭据

## 13. 常见问题

### 工程提示找不到 config

- 没有将 <code>config.example.js</code> 复制为 <code>config.js</code>
- 文件位置不在项目根目录
- 模块导出语法被修改

### 页面一直显示 0

- OneNET 请求失败
- Authorization 错误或过期
- Product ID、Device Name 不匹配
- 物模型标识符与代码不同
- 设备尚未上报数据

### 出粮请求成功但设备没动作

- 请求成功只代表平台接受
- ESP-01S 未订阅或已离线
- STM32 没有收到完整下发帧
- 出粮参数解析失败
- 电机模块故障

### 视频一直显示连接中

- WebSocket IP 错误
- MaixCam IP 已改变
- 不在同一局域网
- 服务没有监听 8765
- 开发环境阻止不安全 WebSocket

### 重复生成健康记录

- 本地 <code>last_eat_cnt</code> 被清除
- STM32 重启后事件序号从 0 开始
- 多台手机各自维护本地去重状态
