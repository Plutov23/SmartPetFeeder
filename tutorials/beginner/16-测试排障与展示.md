# 第 16 课：测试、排障与项目展示

## 这一课要完成什么

学会用固定顺序查问题，并准备一次完整项目演示。

## 排障不是猜

遇到问题时，不要随机换线和改代码。

按照四层检查：

1. 电源和接线
2. 单个模块驱动
3. 模块之间的通信
4. 项目功能逻辑

## 第一步永远先看电源

检查：

- 电压是否正确
- GND 是否连接
- 模块是否发热
- 电机启动时电压是否下降
- 接线是否松动

如果有异味、冒烟或明显发热，立即断电。

## 第二步看最后一条日志

重新上电并保存完整 USART1 日志。

找到最后一条正常信息。

例如最后一行是：

~~~text
[WEIGHT] HX711 peeling start...
~~~

说明 STM32 已经运行到 HX711 附近，应先检查 HX711，而不是先修改小程序。

## 第三步单独测试模块

使用前面课程的最小测试代码：

- OLED 只显示 HELLO
- AHT20 只读取温湿度
- HX711 只读取重量
- 电机只转 200 步
- ESP-01S 只连接 Wi-Fi
- MaixCam 只发送固定状态

单独测试通过后再接回完整系统。

## 第四步沿数据路径检查

小程序没有温度：

~~~text
AHT20
  → STM32 日志
  → ESP-01S
  → OneNET 属性
  → 小程序请求
  → 页面显示
~~~

点击出粮没有动作：

~~~text
小程序请求
  → OneNET 下发
  → ESP-01S
  → STM32 日志
  → 电机驱动
  → 机械出粮
~~~

找到第一个不正常的边界，问题通常就在它前后。

## 必须完成的测试

### 重复出粮

分别测试 5 g、20 g、50 g。

每个重量至少重复 5 次，记录平均误差和失败次数。

### 连续运行

先运行 30 分钟，再逐步增加到数小时。

记录：

- 是否重启
- 是否断网
- 重量是否漂移
- 电机是否发热
- 视频是否掉线

### 断网恢复

关闭热点，再重新打开。

观察设备是否自动恢复，或者是否给出明确错误。

### 重启恢复

分别重启 STM32、ESP-01S 和 MaixCam。

记录哪些数据会丢失。当前喂食计划只保存在 STM32 内存中。

## 项目演示顺序

建议按下面顺序演示：

1. 用一句话说明项目解决的问题
2. 展示系统架构图
3. 展示 OLED 和传感器
4. 展示 5 g 手动出粮
5. 展示定时计划
6. 展示 MaixCam 识别
7. 展示小程序和进食记录
8. 说明当前限制
9. 展示 GitHub 和教程

## 演示前准备

- 稳定的独立热点
- 备用电源
- 少量相同规格宠物粮
- USB 转串口
- 一份成功日志
- 一段备用演示视频
- GitHub 仓库二维码

备用视频不是作弊。它用于网络或现场硬件突然异常时，继续说明项目流程。

## 如何介绍项目限制

可以主动说明：

- 视觉状态是简单规则，不是专业行为模型
- 计划重启后会丢失
- 小程序记录保存在本机
- 原型还缺少完整堵转和异常保护

能够说清限制，说明你真正理解了项目。

## 下一步可以改进什么

优先顺序：

1. 增加出粮上限和电机保护
2. 给 HX711 增加超时和滤波
3. 保存计划和标定参数
4. 增加 Wi-Fi 自动重连
5. 使用后端保护云平台凭据
6. 改进视觉状态判断
