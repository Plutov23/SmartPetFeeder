# 第 5 课：让 STM32 向电脑发送文字

## 这一课要完成什么

在电脑上看到 STM32 发出的文字。

这些文字叫作“日志”。以后设备出错时，日志能告诉我们程序运行到了哪里。

## 什么是串口

串口是一种简单的文字通信方式。

本项目使用 USART1 连接电脑：

~~~text
STM32 → USB 转 TTL → 电脑串口助手
~~~

## 需要准备

- STM32 开发板
- USB 转 TTL 模块
- 杜邦线
- 串口助手
- 已经烧录项目固件

## 接线

| STM32 | USB 转 TTL |
| --- | --- |
| PA9 / TX | RX |
| PA10 / RX | TX |
| GND | GND |

只看日志时，PA10 可以暂时不接。PA9 和 GND 必须连接。

不要同时用 USB 转 TTL 的电源脚和其他电源重复给开发板供电，除非已经确认供电方式。

## 打开串口助手

选择 USB 转 TTL 对应的串口号。

设置：

~~~text
波特率：9600
数据位：8
停止位：1
校验位：无
流控：无
~~~

“波特率”可以理解成双方约定的通信速度。两边设置不同，就容易出现乱码。

## 查看项目自带日志

当前项目已经把日志发送到 USART1。

打开串口后，按一下 STM32 复位键。

## 正确现象

你应该看到类似内容：

~~~text
[00000000][SYS] Board power on...
[00000125][WEIGHT] HX711 peeling start...
~~~

方括号里的数字是程序运行的毫秒数。

<code>SYS</code>、<code>WEIGHT</code> 是模块名称。

如果你还没有连接 HX711，日志可能停在称重初始化附近。这一课只要求看到第一条启动日志。

## 自己增加一条日志

打开 <code>Core/Src/main.c</code>。

在 <code>USER CODE BEGIN 2</code> 后加入：

~~~c
APP_LOG("LEARN", "Hello, SmartPetFeeder!");
~~~

重新编译、烧录并复位。

## 正确现象

串口中出现：

~~~text
[运行时间][LEARN] Hello, SmartPetFeeder!
~~~

这说明：

- STM32 正在运行
- USART1 正常
- USB 转 TTL 接线正确
- 串口助手设置正确

## 完全没有文字

依次检查：

1. 是否选择了正确串口号
2. 波特率是否为 9600
3. PA9 是否连接 USB 转 TTL 的 RX
4. GND 是否共地
5. 工程是否成功烧录
6. 是否按了复位键

## 出现乱码

- 波特率不是 9600
- 数据位、停止位或校验位设置错误
- 供电或接线不稳定
- 选择了错误的串口

## 日志只出现一半

先保存已经看到的文字。

最后一行通常能帮助判断程序停在哪个模块。不要只说“程序卡住了”，应把最后几行一起记录。

## 实验完成后

可以保留 <code>LEARN</code> 日志，也可以删除。

以后每增加一个模块，都要先查看串口日志。

## 这一课的完成标准

- [ ] USART1 接线正确
- [ ] 串口助手设置为 9600、8N1
- [ ] 能看到 Board power on
- [ ] 能看到自己添加的 LEARN 日志
- [ ] 知道乱码时先检查波特率
- [ ] 知道日志最后一行可以帮助定位问题
