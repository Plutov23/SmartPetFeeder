# 第 15 课：组合完整智能喂食器

## 这一课要完成什么

把前面单独验证过的模块组合起来。

这一课不再学习新模块，重点是按照顺序联调。

## 先清理临时测试代码

打开 <code>Core/Src/main.c</code>。

删除前面课程加入的：

- LED 闪烁循环
- OLED 独立测试
- AHT20 独立测试
- DS1302 独立测试
- HX711 独立测试
- 电机固定步数测试
- Wi-Fi 和 OneNET 固定数据测试
- 临时 <code>while (1)</code>

保留项目原本的完整初始化和主循环。

编译并确认 0 Error。

## 确认三个本地配置

| 文件 | 内容 |
| --- | --- |
| <code>app_config.h</code> | STM32 的 Wi-Fi、OneNET 和出粮参数 |
| <code>vision/maixcam/config.py</code> | MaixCam 的 Wi-Fi、串口和模型 |
| <code>miniapp/wechat/config.js</code> | 小程序的 OneNET 和视频地址 |

这三个文件都不应提交到 Git。

## 不要一次全部接上

按照以下顺序组合：

1. STM32、ST-Link 和 USART1
2. OLED、AHT20、DS1302
3. HX711
4. ULN2003 和电机
5. ESP-01S
6. MaixCam
7. 微信小程序

每增加一组，都先运行几分钟。

## 推荐启动顺序

1. 打开路由器或手机热点。
2. 打开 OneNET 控制台。
3. 启动 MaixCam，等待模型和 WebSocket 就绪。
4. 给 STM32 上电。
5. 打开 USART1 日志。
6. 等待 ESP-01S 连接完成。
7. 打开微信小程序。
8. 最后连接或启用电机负载。

## 启动日志应该经过什么

依次观察：

~~~text
Board power on
Schedule module initialized
HX711 peeling start
Tare done
Wi-Fi connection result
MQTT Init steps finished
Starting MaixCam UART
Ready
~~~

日志停在哪一行，就先检查下一步正在初始化的模块。

## 测试一：本地显示

确认：

- OLED 显示时间
- 时间每秒变化
- 余粮百分比合理
- AHT20 有成功日志
- HX711 重量稳定

## 测试二：云端数据

确认：

~~~text
传感器 → STM32 → ESP-01S → OneNET → 小程序
~~~

改变重量后，USART1、OneNET 和小程序中的数字应依次变化。

## 测试三：手动出粮

先选择 5 g：

1. 小程序发出请求。
2. OneNET 下发命令。
3. USART1 出现 Manual feed。
4. 蜂鸣器提示。
5. 电机转动。
6. 实际有粮食落下。

每个步骤都通过，才算完整成功。

## 测试四：定时出粮

设置一个未来 2 分钟的计划。

确认：

- STM32 收到计划
- DS1302 时间正确
- 到点只执行一次
- 出粮重量在可接受范围

## 测试五：进食记录

先用串口模拟：

~~~text
CAT,EATING
NONE,NONE
~~~

两条状态之间等待至少 5 秒。

确认 OneNET 和小程序出现进食记录。

模拟通过后，再测试真实 MaixCam。

## 测试六：视频

确认小程序能看到：

- MaixCam 画面
- 宠物状态标签
- 网络断开提示

视频断开不应影响 STM32 的本地称重和定时喂食。

## 出现问题时怎么退回

如果增加 MaixCam 后系统异常：

1. 先断开 MaixCam。
2. 确认其他功能恢复。
3. 单独测试 MaixCam UART。
4. 修复后再接回。

其他模块也使用同样方法。

## 完整验收

- [ ] 连续运行至少 30 分钟
- [ ] OLED、时间和传感器正常
- [ ] OneNET 持续收到数据
- [ ] 小程序能显示数据
- [ ] 5 g 手动出粮通过
- [ ] 定时出粮只执行一次
- [ ] MaixCam 状态能到达 STM32
- [ ] 进食记录能到达小程序
- [ ] 视频能够显示
- [ ] 电机运行时系统不重启
